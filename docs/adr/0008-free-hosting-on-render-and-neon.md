# ADR-0008: Host the live demo on Render and Neon free plans

- **Status:** Accepted
- **Date:** 2026-10-05

## Context

The project needs a public live demo, so reviewers can try the API in Swagger UI without installing anything. The budget is zero, and no credit card should be required.

Free plans checked in October 2026:

| Platform | App | Database | Card |
|---|---|---|---|
| Render | Free forever: 512 MB RAM, 0.1 CPU, Docker; sleeps after 15 min idle | Free Postgres deleted after 30 days | Not required |
| Neon | – | Free forever: 1 GB, PostgreSQL 18, `btree_gist`; sleeps after 5 min idle | Not required |
| Railway | $1/month credit, about 0.5 GB RAM | – | For paid plans |
| Fly.io | Trial only (2 hours or 7 days) | Managed Postgres from $38/month | Required |
| Koyeb | No free web plan | Requires a paid plan | – |

## Decision

- **App:** Render free web service, built from the `Dockerfile`, in the Frankfurt region (closest to South Africa). Configured as code in `render.yaml`.
- **Database:** Neon free plan, in AWS Frankfurt, through the **direct** (not pooled) connection, because Neon's pooler runs in transaction mode, which migration tools like Flyway don't support.
- **Secrets:**
  - The database login is entered once in the Render dashboard.
  - The JWT key is generated by Render (`generateValue`).
  - None of them are stored in Git.
- **Deploys:** Render deploys a `main` commit only after its CI checks pass (`autoDeployTrigger: checksPass`).
- **Demo data:** the `demo` profile creates a sample salon with services on first start. Its owner's password is random and never shown.

### Fitting Spring Boot into 0.1 CPU and 512 MB

Measured locally with `docker run --cpus=0.1 --memory=512m`:

| Change | Startup | Memory |
|---|---|---|
| Plain image | 216 s | 314 MB |
| + Java 25 AOT cache (training run during the image build) | about 165 s | about 305 MB |
| + lazy initialisation | no improvement, not used | – |

- **AOT cache settings:**
  - A fixed heap (`-Xmx320m`), so the cache's memory layout always matches.
  - `-XX:-AOTClassLinking`: with pre-linked classes, a layout mismatch inside a memory-limited container made Java **refuse to start**. Without them, a mismatch just means a normal start.
  - 84% of classes load from the cache.
- **Connections:** the connection pool closes idle connections after 60 s and keeps none open, so Neon can sleep instead of using up its free compute hours. Measured: 0 open connections after 75 s idle.

## Consequences

- **Cold starts take about 3 minutes** on 0.1 CPU after the app has slept. Mitigation: an external uptime monitor (UptimeRobot, set up on 2026-10-06) calls `/livez` every 5 minutes. That keeps the app awake (744 hours a month at most, within Render's 750 free hours) and emails an alert if the demo goes down. `/livez` only checks that the app process is running and never touches the database, so Neon can still sleep.
- **Requests are fast once the app is running:** about 0.4 s measured.
- **Metrics port 9090 stays private:** Render routes public traffic only to the `PORT` port. Other ports are reachable only on Render's private network.
- **Client IPs:** with `server.forward-headers-strategy=native`, Tomcat takes the client IP from `X-Forwarded-For` but trusts only proxies on internal networks, so clients can't fake their IP to get around the per-IP login limit.
- **Limits that come with the free plans:**
  - one instance
  - no database backups on Neon's free plan; data is demo-only
  - a 1 GB storage limit
- **Moving to paid plans** later needs no code changes: only the `plan` in `render.yaml` and the Neon project settings.

## Alternatives considered

- **Render's own free Postgres:** deleted after 30 days.
- **Fly.io / Railway / Koyeb:** no lasting free option for this app.
- **GraalVM native image:** much faster startup and less memory, but a longer and more fragile build, and some libraries need extra configuration. Worth revisiting if cold starts matter more.
- **Lazy initialisation:** measured, no gain.
